# R3.3 — Components, Variants, and Instances

**Status: LIVE-ACCEPTED 2026-09-24 on the R3.3 pair `r3.3-server-a472b2a4cb3e` ↔
`r3.3-plugin-06a6fcd0c5ec`, after four offline fix rounds and four live runs
([Live acceptance record](#live-acceptance-record-verifier)). Release replay complete (all 24

R3.3 is Phase 3 of the R3 re-cut ([`R3-RETROSPECTIVE.md`](R3-RETROSPECTIVE.md) § Phase 3):
generic, local-only authoring of components, component sets (variants), component properties,
instances, and slots. It also owns the one premise R3 left unmeasured: whether an existing write
tool works on a node **inside an instance** (`live-clips-content-gate.mjs`, `stillOwed`). It does
not promote any R3.1 or R3.2 preview tool, and it does not change any stable tool.

Baseline it starts from: **R3.2.1 / `1.21.0` / 87 tools**, pair `r3.2.1-server-798028241619` ↔
`r3.2.1-plugin-d9b64d2ac562` (fingerprint `sha256:f6f9c2bb…`), offline **485/485**, release replay
**25/25** on channel `m5g7y5fg`, contract frozen as `contracts/baselines/r3.2.1-public-contract.json`.

## 1. Local-identity and rerun rule

1. Every mutation starts from an exact node ID resolved through `figma.getNodeByIdAsync()` and
   checked for the expected type, `remote === false` (components and sets), and a page ancestor
   (a soft-deleted main component or a detached orphan has none). Anything else refuses before a
   native write. An explicit ID never falls through to a name lookup, a key lookup, or a create.
2. A component's Figma `key` is diagnostic only: never a selector and never a cross-file identity.
   The one place the Plugin API requires keys — `preferredValues` on INSTANCE_SWAP and SLOT
   properties — takes **exact local component or set IDs** from the caller; the tool derives each
   key only after resolving that node as exact local.
3. Names are not identity. A component property is addressed by the exact suffixed key Figma
   returned (`Label#4:0`); a VARIANT property by its exact name. A key is never guessed or
   reconstructed. Adding a property whose name already exists on the node refuses.
4. `identityKey` is opaque, 1–2048 characters, stored as this plugin's private plugin data,
   compared byte for byte, never echoed in a receipt (report `identityKeyStatus`), and never
   treated as secret material. Reuse R3.2's validation (`requireLocalStyleIdentity` pattern) with
   a separate node-scoped plugin-data constant.
5. The key is **required** on `create_or_match_component`, `create_component_from_node`, and
   `combine_as_variants` (stored on the set), and **optional** on `create_or_match_instance`.
   Property and instance mutations act on explicit IDs and take no key.
6. Component and set resolution: (a) a **document-wide** scan — per-page `loadAsync()` plus
   `findAllWithCriteria({ types: ["COMPONENT", "COMPONENT_SET"], pluginData: { keys: [K] } })` —
   for nodes whose stored value equals the key exactly: one match → `matched` after verifying its
   type (and, for a set, its members); several → `identity_key_conflict`; a scan that cannot
   finish → `identity_scan_incomplete`, because uncertainty never grants a create; (b) no match →
   refuse on a **sibling** name collision (same parent, same type, same name, absent or different
   key); (c) create, then store the key. The receipt carries
   `identityScan: { pagesScanned, pagesTotal, complete }`.
7. Instance resolution with a key: scope = the explicit parent's direct children. One INSTANCE
   bearing the key → `matched` only if its main component is the requested component (or the
   requested variant), else `identity_key_conflict`; none → create; several → refuse. Without a key
   the call is a plain create with `identityKeyStatus: "none"`, and the receipt states that a rerun
   will create another instance.
8. A create-or-match receipt names `created`, `matchedBy`, `id`, `type`, and `identityKeyStatus`
   (`written` | `matched` | `none`). It never implies a node ID is portable across files.
9. The handlers must not depend on how Figma treats plugin data across `combineAsVariants`,
   `createComponentFromNode`, or `detachInstance` (premises P1, P2, P4, P11). They re-resolve after
   the call and report what they observed.

## 2. Remote-refusal rule

1. R3.3 never imports, publishes, or mutates a remote component or component set. No R3.3 handler
   calls `importComponentByKeyAsync`, `importComponentSetByKeyAsync`, or any key-based lookup, and
   none writes to a node whose `remote` is `true`. Refusal: `remote_component_refused`, before any
   native call.
2. The test for an instance write is whether it **introduces** a remote reference:
   - **Allowed** on an instance whose main component is remote: TEXT and BOOLEAN property values,
     `reset_instance_overrides`, and a top-level `detach_instance`. These change only the local
     instance; the receipt discloses `mainComponent.remote: true`.
   - **Refused** (`remote_reference_refused`): a remote swap target, a remote INSTANCE_SWAP value
     or preferred value, and a VARIANT change on an instance whose main is remote (it re-points the
     instance to another remote variant).
3. Replacing a remote reference with a verified local one (swapping a remote-main instance to a
   local component, or setting an INSTANCE_SWAP to a local component) is allowed: it changes the
   local node, not the remote resource. The receipt reports the prior remote reference.
4. `get_component` reads local nodes. A remote COMPONENT or COMPONENT_SET ID refuses, as R3.2's
   `get_local_style` does; an instance's remote main component is reported as
   `{ id, name, remote: true }` without traversing it.
5. The stable `create_component_instance` keeps its `componentKey` import branch unchanged. It is
   the one legacy remote path, documented as outside R3.3's rules; R3.3 adds no second one.
6. Offline, every native mutator and importer is spied on and each remote refusal is proved to
   reach none of them. Live acceptance needs a **real** remote control: an instance of a variant
   from a published library component set in the owner-confirmed disposable file, passed as
   `--remote-instance-id`. The gate refuses to start without it. The control is never fabricated;
   if no disposable file has one, the owner places one there first.

## 3. Ownership, deletion, and cleanup rule

1. Components and sets are page nodes, so deleting a gate's scratch page removes the ones it owns;
   this differs from R3.2's document-scoped styles. But Figma documents that a main component
   deleted while instances exist elsewhere survives, soft-deleted, for those instances — and
   `delete_node` does that silently today. `delete_component` is therefore the owned deletion path:
   - literal `confirm: true`; an exact local standalone COMPONENT or a COMPONENT_SET; a variant
     member refuses (`variant_member_delete_refused`; v1 deletes whole sets);
   - ownership: the node must carry the exact supplied `identityKey`, else `not_owned`;
   - consumers: `getInstancesAsync()` on the component, or on every variant of the set; any
     instance → `component_has_instances` with the count and a bounded list of instance IDs; an
     unavailable read → `consumer_observation_unavailable`, and nothing is deleted;
   - no cascade: it never deletes or detaches an instance;
   - `removed` only with an independent post-removal signal (a fresh `getNodeByIdAsync` returns
     `null` or a node with no page ancestor, and a fresh page-scoped `findAllWithCriteria` no longer
     returns it), naming the signal that fired. Otherwise `removal_unconfirmed` plus a re-read
     instruction — the `delete_variable` lesson: Figma can return a stale object inside the
     deleting frame.
2. `delete_component_property` is destructive (instances lose that property's overrides): literal
   `confirm: true`; VARIANT refuses because the API does not support it; the receipt reports which
   descendants referenced the property before the call and after.
3. Instances and the frames that `detach_instance` produces are deleted with the existing
   `delete_node` or with the scratch page. Instances of owned components never leave the scratch
   page.
4. Before its first mutation, every gate records the page list and current page, the
   `get_local_components` summary (per-page and per-family counts), and the local style and
   variable-collection counts as cheap residue detectors.
5. Ownership is recorded **from the receipt, before asserting** (R3.2 live run 1 left a residue
   style because it recorded ownership after the assertions). A thrown create is recovered by the
   run-stamped identity key. In `finally` the gate deletes its instances and detach frames, deletes
   its owned sets and components through `delete_component` (proving the tool), deletes the scratch
   page, restores the original page, and runs every cleanup step even after one fails.
6. A `finally` attempt is not proof. A fresh, separate client compares the final baseline with the
   original; any mismatch fails the gate and prints the exact owned IDs for manual repair. R3.3 has
   no `--allow-permanent-*` flag.

## 4. Observation rule

1. `get_component` is the canonical bounded projection: `id`, `type`, `name`, `remote`, page and
   parent, `identityKeyStatus`; for a component, `isVariant`, `variantProperties`,
   `componentSetId`, and `componentPropertyDefinitions` (variants point to their set, where Figma
   keeps the definitions); for a set, its variants (`id`, `name`, `variantProperties`, `x`, `y`),
   `defaultVariantId`, and definitions; for an instance, `mainComponent` (`id`, `name`, `remote`,
   `componentSetId`), `componentProperties`, direct `overrides`, and whether it has an instance or
   component ancestor; for a slot, its property key, child count, and `limitViolations`; bounded
   `componentPropertyReferences` of descendants; and, only with `includeInstances: true`, a
   bounded instance list from `getInstancesAsync()`. Mixed, absent, and unreadable values stay
   distinguishable.
2. Every create and mutation receipt carries `before` and `after` projections from fresh reads,
   never from the request; `readbackMatchesRequested` (every requested field reads back equal:
   strings exact, numbers at float32 using the R3.2 `localStyleValueCovers` approach, fields only
   Figma adds reported but not compared); and `outcome: confirmed | unconfirmed | refused`.
3. **Unmeasured premises are never baked into a handler.** Where the platform could go two ways
   (see the register), the handler re-resolves and reports which way it went (`sourceIdPreserved`,
   `memberIdsPreserved`, `identityKeyCarried`, `defaultVariantId`, …), and the offline suite runs
   **both** branches through opt-in harness options, each named after its premise.
4. `get_component` is the tool's own witness, not an independent one. A live gate confirms each
   claimed fact through an **existing** tool on a different code path and in a different currency:
   `get_node_info` (REST-export geometry, fills, characters, children), `export_node_as_image`
   preflight (render bounds — the clips gate's currency), `scan_text_nodes`,
   `get_local_components` (inventory and families), and the override count in
   `get_instance_overrides`'s message. A receipt that agrees with its own projection is not
   evidence.
5. Fixtures must make that currency move: variants differ in size **and** fill; a BOOLEAN-bound
   child extends outside an unclipped instance, so hiding it changes render bounds; the two
   INSTANCE_SWAP targets differ in size.
6. `refused`, `unconfirmed`, `unmeasured`, and `removal_unconfirmed` are public outcomes, never
   aliases of success. Only a discriminating Figma observation may produce `confirmed` or
   `removed`.
7. Offline known-bad fixtures: a remote component and a remote main; the wrong type; a duplicate
   identity key; an incomplete identity scan; a sibling name collision; a `setProperties` that
   accepts and discards the write; a swap whose heuristic drops overrides; a stale post-delete
   read; a consumer read that fails to vary; `createSlot` absent; a nested detach. A green fixture
   that cannot fail under one of these conditions is not acceptance evidence.

## 5. Destructive and structural operations rule

1. **Validate all, then write.** Every input, target, parent, and property is resolved before the
   first native call, so a refusal leaves the document untouched; `create_*` never leaves an
   orphan behind (the R2.6 `create_text` rule).
2. `create_component_from_node` pre-checks Figma's documented restrictions (the node is not a
   component or set and has no component, set, or instance ancestor) before the call. The receipt
   names `sourceNodeId`, the component `id`, and the observed `sourceIdPreserved`.
3. `combine_as_variants` never renames anything. Every member must be an exact local, non-variant
   component on the parent's page, and its name must already parse as `Property=Value` pairs with
   the same property set on every member, non-empty values, and a unique combination per member;
   otherwise `invalid_variant_matrix` before the call. The parent is explicit, a container, and
   not inside an instance. The tool does not move members; the receipt reports their positions and
   the set's `defaultVariantId` as read (Figma defines the default as the top-left-most variant).
4. `detach_instance` requires literal `confirm: true` and, in v1, an instance with **no**
   INSTANCE, COMPONENT, or COMPONENT_SET ancestor. Figma documents that detaching a nested
   instance also detaches every instance ancestor, and detaching an instance inside a main
   component rewrites that component for all of its instances. Both are hidden cascades, so they
   refuse (`nested_instance_detach_refused`, `component_member_detach_refused`) and name the
   ancestor chain. The receipt names `originalInstanceId`, the new `frameId`, the prior main
   component, and the observed `originalIdResolves`, `originalIdType`, and `identityKeyCarried`.
   A FRAME may retain the original ID; confirmation requires that this ID no longer resolves to
   an INSTANCE.
5. `swap_instance_component` takes an exact local COMPONENT (a variant member is allowed) and calls
   `swapComponent`. Figma says its override-preservation heuristic may change, so the receipt
   reports the direct overrides before and after and never promises preservation.
6. `reset_instance_overrides` calls `removeOverrides()` (never the deprecated `resetOverrides`),
   reports the direct overrides before and after, `changed` only when a nonempty direct override
   list becomes empty, and `wrote: false` when none were removed. It does not claim anything about
   inherited overrides.
7. `set_instance_properties` validates every key against the main component's definitions (its
   set's, for a variant) before the call: unknown key, wrong value type, a VARIANT value outside
   `variantOptions`, or a VARIANT combination that resolves to no variant all refuse; SLOT keys
   refuse (Figma throws `cannotSetSlotProperty`); INSTANCE_SWAP values must be exact local
   component IDs. One `setProperties` call per request; the receipt reports every requested key and
   the main component before and after.
8. `bind_component_property` accepts `characters` on a TEXT node (TEXT property), `visible` on any
   node (BOOLEAN), and `mainComponent` on a nested INSTANCE (INSTANCE_SWAP). The node must be a
   descendant of the exact local component — or of a variant of the exact local set — that defines
   the property. `null` clears the binding. Readback is the node's `componentPropertyReferences`.
9. `add_component_property` and `edit_component_property` enforce the support matrix from the
   `@figma/plugin-typings` 1.139.0 documentation before the call. **Add:** BOOLEAN, TEXT, and
   INSTANCE_SWAP on a non-variant component or a set; VARIANT on a set only; SLOT only through
   `create_slot`; a variant member refuses (`variant_member_property_refused`, because its
   definitions live on the set). **Edit:** `name` for every type; `defaultValue` for BOOLEAN, TEXT,
   and INSTANCE_SWAP; `preferredValues` for INSTANCE_SWAP and SLOT; `description` and
   `slotSettings` for SLOT only. The receipt returns the key Figma produced and the definitions
   before and after.

## 6. Slots rule

1. Slots ship only when the running Figma exposes them. Each slot tool checks at call time that
   `createSlot` / `resetSlot` exist and returns `slots_unavailable` otherwise. Slots are never
   emulated with frames and hand-wired properties.
2. `create_slot` acts on an exact local, non-variant COMPONENT (a variant member refuses until
   premise P15 is measured). The receipt reports the new SLOT node ID and the linked SLOT property
   key, both read back from the component's definitions and the slot's references.
3. A slot's settings, description, and preferred values change through `edit_component_property`;
   a SLOT property is deleted through `delete_component_property` with its confirm.
4. Instance slot content goes through the **existing** `set_parent` and `create_*` tools with the
   instance's SLOT node as parent. Whether those handlers accept it is measured (G2 and G3). If they
   refuse or report falsely, R3.3 records the finding; a narrow `append_to_slot` tool is then a
   follow-up decision, never a silent widening of a frozen tool.
5. `reset_slot` acts on an exact SLOT node inside a local instance and reports the child count and
   `limitViolations` before and after. `limitViolations` is reported, never enforced by the fork:
   Figma's slot settings are the authority.

## 7. Instance-child eligibility rule

1. Platform fact: for an owned local instance of an owned component, which existing write tools
   Figma accepts on the instance's children, and whether each handler reports the outcome honestly
   (a readable property is not always a writable one).
2. One dedicated gate (G3) runs a fixed matrix, each row on a child whose pre-write value differs
   from the requested one. Hypotheses, not assertions:
   - value overrides expected to apply: `set_fill_color`, `set_stroke_color`, `set_corner_radius`,
     `set_opacity`, `set_effects`, `set_text_content`, `set_clips_content` (nested frame — the
     recorded premise), `set_layout_sizing` and `set_padding` (nested auto-layout frame),
     `resize_node`, `rename_node`;
   - structural writes expected to be refused: `set_parent` out of the instance, `delete_node`
     on a child, `create_frame` with the instance as parent, `create_group` over an instance child.
3. Per-row verdict, from `get_node_info` on the instance child **and** on the main component's
   matching child: `applied_as_override` (child changed, main unchanged), `refused_by_handler`
   (typed, child unchanged), `refused_by_platform` (Figma's error text, child unchanged),
   `false_success` (the receipt claims success, the child is unchanged) → **gate FAIL**,
   `refused_but_mutated` (the call refused but the child changed) → **gate FAIL**,
   `leaked_to_main` (the main component changed) → **gate FAIL**, or `unmeasured` (the row could
   not be set up), which is recorded and never counted as a pass.
4. Controls: the same write on the matching child of a plain frame must apply, and on the main
   component's child must apply to the main (restored afterwards), so a row cannot pass on a tool
   that is broken everywhere.
5. A finding on a stable tool is recorded, not fixed in R3.3 (it is an R3.4 contract decision). A
   finding on an `additive-preview` tool may be fixed in R3.3 with a killable test.
6. `live-clips-content-gate.mjs` §5 gains the instance-child context, built with R3.3 tools, and
   its `stillOwed` line is removed only when that row has measured. The clips gate and the G3 clips
   row must agree.

## 8. Compatibility and delivery rule

1. `create_component_instance`, `get_instance_overrides`, and `set_instance_overrides` keep their
   inputs, results, and behaviour byte for byte. Every frozen baseline in `contracts/baselines/`

## Acceptance matrix

| Scenario | Required discriminating fact | Failure / unmeasured outcome |
| --- | --- | --- |
| Identity and rerun | The same request matches its owned component, set, or keyed instance and adds no node; a wrong key, name collision, or duplicate refuses with zero native writes. | Typed refusal; no promotion. |
| Remote | Every remote path refuses before any native mutator or importer; the control instance is unchanged. | `unmeasured` only if no real control exists — and the gate will not start without one. |

| Detach | The old ID no longer resolves to an INSTANCE, a FRAME exists, and nested or in-component detaches refuse. | `unconfirmed`. |

| Runtime boundary | A bad pin exits before the baseline or any mutation. | Gate FAIL if a write is reachable. |
