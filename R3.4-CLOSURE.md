## Move 1 — R3.3.1, the consumer fix

**In scope:** 1A–1E, and contract `1.23.0`. The `get_node_variables` and `export_node_as_image`
result and failure shapes grow, so `serverSchemaVersion` moves and the fingerprint moves with it
(the R1 rule). **Out of scope:** every stable tool's result shape, every promotion, and every R3.3
tool.

### 1A. The Symbol record contract

`readStyleValue()` copies eight TextStyle fields verbatim in its TEXT branch. On the consumer's
remote TEXT styles at least one of them is a Symbol. `postMessage` cannot clone a Symbol, so one
record costs the whole reply. The existing `read_failed` status only catches a throw, so it never
fires.

- Every branch of `readStyleValue()` (PAINT, TEXT, EFFECT, GRID) is walked for Symbols at any depth,
  not only TEXT's top level.
- A Symbol becomes `null` inside `value`, and the record's `unreadableFields` names it:
  `{ "path", "reason", "description" }`. `reason` is `figma_mixed` when the value is `figma.mixed`
  and `symbol` otherwise. `description` is the Symbol's description, or `null`.
- A record with any unreadable field reports `valueStatus: "partial"`. A fully read record carries
  `unreadableFields: []`, so the list is present wherever a value was read.
- ⛔ **Never a silent `null`.** Every `null` this rule produces is named in `unreadableFields`.
- Variable values follow the same rule on the two **preview** read paths: `get_node_variables`
  bindings (`resolveNodeBinding`) and `get_variables` values. The shared serializer also feeds the
  stable `set_variable_value` readback. That path keeps its frozen shape in move 1 and reaches the
  boundary (1B) instead. Every variable binding on the consumer's fixture serialized, so this half
  is latent, not observed.
- `get_node_variables`' description documents `partial` and `unreadableFields`. Its limitation
  text counts partial records the way it already counts `read_failed` ones.

Shape only. The field name comes from the diagnostic (P23), never from this example:

```json
{
  "styleType": "TEXT",
  "remote": true,
  "value": { "fontSize": 16, "<field named by P23>": null },
  "unreadableFields": [{ "path": "<field named by P23>", "reason": "figma_mixed", "description": null }],
  "valueStatus": "partial",
  "resolutionStatus": "resolved"
}
```

### 1B. The response boundary

Every command result leaves the plugin through one `figma.ui.postMessage({ type: "command-result",
… })` in the `execute-command` handler. A clone failure there surfaces today as the platform's
opaque `in postMessage: Cannot unwrap symbol`, which names neither the record nor the field.

- When posting a result throws, the plugin scans that result, cycle-safe and bounded to the first
  ten hits. It then posts a `command-error` whose message begins `unserializable_result:` and names
  the command and each Symbol path, for example `unserializable_result: get_node_variables returned
  a Symbol at styles[3].value.<field>`.
- If the scan finds no Symbol, Figma's original text is kept verbatim.
- ⛔ The boundary never rewrites, drops, or replaces a value. A reply either posts whole or fails
  with a location. It is the net under 1A, not a substitute for it.
- Offline, the harness's `postMessage` fake refuses a Symbol with the observed text `in
  postMessage: Cannot unwrap symbol`. The known-bad leg is today's boundary, which must fail the
  path assertion.

### 1C. Diagnostic before fixture

The field and the Symbol's identity are still unknown: the brief says "presumably `figma.mixed`".
R1 read 318 remote TEXT style references on the SYD file without a crash, so the trigger is
specific to certain styles. The order is fixed:

1. **Run the live known-bad leg on the unfixed R3.3 pair.** The verifier sweeps the disposable file
   for TEXT nodes whose `textStyleId` is remote and calls `get_node_variables` on each. This is
   read-only, and its instruments live in `docs/r3.3.1-verifier/`. A crash on a node is the
   reproduction. If none crashes, the owner places one instance from the consumer's UI-kit library,
   whose `Button`, `Input field` and `Dropdown` components held every culprit, and the sweep
   re-runs.
2. **Codex builds 1A and 1B with mechanism tests only.** A synthetic Symbol at an arbitrary path
   proves the fork's own invariant. It claims nothing about which field Figma makes a Symbol.
3. **The fixed build is the diagnostic.** Run read-only on the reproduction, it names the field or
   fields and the Symbol's identity. That is premise **P23**, recorded in this file.
4. **Only then write the premise fixture:** a fake modelled on P23. It must fail against the
   unfixed `readStyleValue` (mutation-proven) and pass on the fix.

If P23 contradicts 1A (for example, a Symbol that the walk cannot reach), the design comes back to
this file before any fixture is written.

### 1E. The SVG export error

`exportNodeAsImage` rethrows `Error exporting node as image: ${error.message}`. When `exportAsync`
rejects with a non-Error value, `.message` is `undefined`, and the server wrapper adds a second
prefix. The live reply was `Error exporting node as image: Error exporting node as image:
undefined`. The progress line just above already uses `error.message || String(error)`, so the
real text was available and then dropped. No R3.3 report captured it.

- Keep Figma's text (`error.message || String(error)`) and its type in the thrown error. The server
  does not prefix a second time.
- ⛔ Never fall back silently to another format. An SVG request never returns PNG bytes.
- Whether Figma can export that instance as SVG at all is Figma's behaviour. It is measured as P24,
  not fixed here.

### 2A. Stable-tool additive disclosure

| Tool | Recorded defect | Disclosure |
| --- | --- | --- |
| `resize_node` | False success inside an instance (G3, P16) | A receipt with the requested size, the size read back, and `applied: false` when Figma kept the old size |
| `create_frame` | A slot insertion replies with the pre-insertion ID, which is an alias (P22) | A receipt with `canonicalId`, and whether the reply ID is an alias |
| `set_parent` | A slot insertion reports no ID, and the original resolves as an alias (P22) | A receipt with the canonical post-move ID and the original ID |
| `get_instance_overrides` | The plugin returns `mainComponentId`, and the wrapper drops it | A receipt with `mainComponentId` and the override count. The description points to `get_component` |
| `create_component_instance` | Imports by key, creates before resolving `parentId`, and appends to the current page on a bad parent | Description only: it points to `create_or_match_instance` |
| `set_instance_overrides` | One instance can be reported both failed and succeeded | Description only: it points to `set_instance_properties`, `swap_instance_component` and `reset_instance_overrides` |

- The four tools that gain a receipt all reply in prose today. R2.4 measured the cost of that: a
  field that a prose wrapper drops never reaches the consumer. So each keeps its historical line
  **byte-identical** and appends a JSON receipt beneath it, as `create_text` did in R2.6. Sixteen
  gates call `create_frame`, and 14 gate scripts parse an ID out of a `with ID:` reply line.
- G2 and G3 hold these defects as exact-match known findings, so their classifiers change in the
  same Codex change. Each is proven both ways: the R3.3.1 pair still yields the old finding, and
  the R3.4 pair yields the disclosure. A loosened gate needs a known-bad rerun.
- `get_instance_overrides` gains a read-only row in G1 that compares `mainComponentId` with
  `get_component`.
- No live gate calls `create_component_instance` or `set_instance_overrides`. Their change is
  description text only, so it needs no gate.
- The R3.4 record carries the migration note and the consumer note that
  [`docs/COMPATIBILITY-POLICY.md`](docs/COMPATIBILITY-POLICY.md) requires for a stable tool.

## R3 acceptance (from `TASKS.md`, unchanged)

Generic MCP clients can measure and author local design-system resources and component primitives
through documented Figma-native contracts. Every claimed live behaviour has a discriminating gate,
and every remaining unknown is explicit. R3.4 closes R3 when every stability decision above is
explicit and the whole roster is green on the R3.4 pair.

## Named unknowns (not assumed)

- **P23:** which TextStyle field is a Symbol, and whether it is `figma.mixed`.
- **P24:** Figma's own SVG rejection text for a BOOLEAN-bound instance.
- Whether the disposable file already holds a remote TEXT style that crashes, and whether it holds
  a prototype reaction.
- Whether a variable value can ever be a Symbol. This is latent and has never been observed.

## Non-goals

- Fixing Figma's SVG behaviour.
- Any write to a consumer file, and the consumer's own acceptance.
- Library import or publishing.
- A breaking change to any stable tool.
- Promoting `delete_variable_collection`.
- Adding R3.3 tools to `apply_batch`.
- Checking progress-update payloads for Symbols. The fork builds them itself, and none has failed.
