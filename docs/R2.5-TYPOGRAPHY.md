## Phase 1 — the two text defects (2026-08-18)

- **F1, the mixed-font crash, was one redundant line.** `setTextContent` pre-loaded
  `node.fontName`, which is `figma.mixed` — a symbol — on a multi-font node.
  `setCharacters` on the next line already branches on `figma.mixed` and loads a concrete
  font in every branch, so the pre-load did no work and was the only thing that threw.
  One deletion fixed the single *and* the batch tool, which share the defect site.
- **F3 confirmed, not just hypothesised.** Given a refused character write the old code
  returned a success reply and the batch reported `all_succeeded` over an unchanged
  document. `setTextContent` now honours `setCharacters`'s `false` return.
- **F2's silent Inter substitution is now reported** — `fontSubstituted` /
  `requestedFont` / `appliedFont`, with `false` on the ordinary path so an absence is
  never mistaken for a fact.
- ⚠️ Phase 1 was **not** contract-neutral, contrary to the plan's first description: it
  adds fields to `set_text_content`, whose stability is `stable`, and free result fields
  are granted only to `legacy`/`additive-preview`. The `stable`-by-default trap fired
  inside Phase 1, before any new tool existed. That is what spent R2.5's one bump.

## Phase 2 — the bounded font inventory and preflight (2026-08-18)

`get_available_fonts` and `check_fonts`, the release's first new tools, both
`additive-preview` per **CC1** in the same commit that registers them.

- **`available` and `loadable` are two fields because they can disagree.** A face can be
  listed and still refuse to load, and `setCharacters` answers that refusal by
  substituting Inter silently. One field would have answered `true` and let the
  substitution happen — a *consistency* check standing in for a *correctness* check.
  `familyAvailable` is a third fact, separating "Inter has no Blond" from "this machine
  has no Ghost": opposite fixes.
- 🔴 **The plan was wrong about `timeBudgetMs` and the reply says so.**
  `listAvailableFontsAsync()` takes no cancellation signal, so a budget bounds the
  **reply** and the call is *abandoned*, not stopped. `coverage.budgetCancelsFetch: false`
  is a permanent declaration, because a bare `budgetExhausted` reads as "work was
  skipped".
- **Absent counts are `null`, never `0`** — a `0` reads as "this machine has no fonts", a
  real finding rather than the absence of one.

## Phase 3 — the typography write surface (2026-08-19)

`set_text_style(nodeId, …)` — twelve optional typography parameters, at least one
required, node-level per **D2**. `additive-preview` per **CC1**, `standard` timeout,
`write` direction, `node` scope, and **no** progress declaration (CC2: it touches one
node and has no point worth reporting from; declaring progress it does not emit would be
Finding 4 a third time).

### The three decisions taken at interview

1. **3.5 is deferred to R2.6.** `create_text` is `stable` — it falls through
   `getResultStability` — and `COMPATIBILITY-POLICY.md` grants free result fields only to
   `legacy`/`additive-preview`, so giving it new reply fields needs a new contract
   version. R2.5 already spent its bump in Phase 1 and R2.6 owns `1.8.0`. ⭐ The collision
   is real and was found before it was paid for: the alternative was shipping a
   `create_text` that takes a font it cannot report substituting, which is F2 on a new
   surface. R2.6 can fix the hardcoded Inter **and** the deferred un-awaited
   `setCharacters` at `code.js:1790` in one change, under a bump it already owns.
2. **⛔ An unloadable font is REFUSED, never substituted.** This is the one place
   `set_text_style` deliberately diverges from `set_text_content`. `setCharacters`
   answers a refused load by retyping the node to Inter — F2, the defect Phase 2's
   `check_fonts` exists to let a caller avoid. Repeating it here would change the
   document's font as a side effect of a call that asked for a size. The font is probed
   inside the **validation** phase, so a refusal writes nothing at all.
3. **`fontSubstituted: false` is a permanent declaration, not a state.** The same shape
   as `coverage.budgetCancelsFetch`. It says the question was considered and cannot arise
   here, where an absent field would leave a reader unable to tell "no" from "not
   reported".

### 3.2 — validate-all-then-write, from birth

⛔ Non-negotiable, and the reason is specific: this is a twelve-field write, the exact
shape **F4** proves broken in three ops that ship today. `setAxisAlign` writes at `:5816`
and throws at `:5835`; `setLayoutSizing` writes `:5896`, throws `:5922`; `setItemSpacing`
writes `:5970`, throws `:5984` — each leaving a `failed` result on top of a changed
document. Building this one the same way would have minted a fourth instance in the
release that pays the first three off.

The handler is therefore two phases with a hard line between them:

- **Validation** — every parameter checked, **all** errors collected rather than the
  first, the `fontFamily`/`fontStyle` pair enforced, and every font the node carries
  loaded **plus** the requested one. Nothing is assigned.
- **Write** — a loop that cannot fail, because every value is validated and every font
  loaded. ⛔ The guarantee lives in that loop being unable to reject, not in a comment
  saying so.

⭐ **Font loading is not a document write.** It mutates the plugin session's font cache
and nothing in the file — the same reasoning that classifies `check_fonts` as a read.
That is what makes a load probe legal inside a validation phase.

⭐ **The node's existing faces are read with `getRangeAllFontNames`, not `fontName`.** On
a mixed node `fontName` is `figma.mixed` and names no face at all, so "load the node's
font" would load nothing and Figma would then refuse the write for a font we never saw.
Figma refuses to modify **any** property of a text node whose current fonts are unloaded
— not only the font — so even a bare `textAlignHorizontal` change loads them first.

### 3.3 / 3.4 — declared semantics

- Supplying `fontFamily`/`fontStyle` **unifies** a mixed node and reports `wasMixed:
  true`; omitting them applies the non-font properties and leaves the font mixed.
  ⚠️ Unification **discards the per-character font runs**, which is a document change
  wider than the property named, so it is stated in `limitations` rather than left to be
  discovered.
- **`fontFamily` and `fontStyle` are one decision, not two.** Half a pair is refused: a
  family without a style has no single answer on a mixed node, and inventing the missing
  half is the silent substitution this tool exists to refuse.
- `lineHeight` / `letterSpacing` are `{value, unit}` objects, never bare numbers — a
  number-typed schema here would be a breaking correction later. `lineHeight` accepts
  `AUTO`, and ⛔ **refuses a `value` alongside it rather than discarding one**: a
  discarded value reads as an applied one.

### ⛔ The `figma.mixed` serialization trap

`JSON.stringify` renders a symbol as `undefined`, which **drops the key**. A mixed
`fontName`, `fontSize`, `textCase` — any per-range property — would therefore have
*vanished* from the reply and read as "not reported" rather than "this node holds more
than one value". Every read-back goes through a sentinel that maps a symbol to the string
`"MIXED"`, and the test asserts the key survives the JSON round trip an MCP consumer
actually receives.

### CC6 — mutation-tested against the SOURCE, five ways, all killed

| Mutation | Killed by |
| --- | --- |
| Move the refusal **after** the write loop (validate-all, write-all, then throw) — the F4 shape | **5** tests |
| Substitute Inter instead of refusing an unloadable font | **3** tests |
| Drop the `figma.mixed` → `"MIXED"` sentinel | 1 test |
| Report only the first invalid parameter | 1 test |
| Read `fontName` instead of `getRangeAllFontNames` | 1 test |

⭐ **The first mutation is the one that matters, and a throw-only test would have survived
it.** Asserting that a call threw does not assert *when* it threw. Every refusal case
therefore asserts the **side-effect channel is empty** — the node's eleven writable
properties, byte-for-byte — and places the invalid parameter **last**, so a
validate-as-you-go implementation would have written the other eleven before reaching it.

⛔ **CC6, stated rather than implied:** the harness supplies the font inventory and
decides which faces refuse to load. The offline suite proves the **order of operations**,
the refusal policy and the mixed-font semantics. It does not prove what real Figma
refuses, or when.

### The two assertions that only Figma can judge

- ✅ **Validate-all-then-write held live.** Eleven valid parameters plus a bad enum
  **last** → refused, and the node is byte-identical on **both** channels: the
  independent REST read (`fontSize` still 32, not the 64 in the payload;
  `textAlignHorizontal` still `CENTER`, not `LOWER`) *and* the plugin's own snapshot,
  which covers the six fields REST cannot see.
- ✅ **Refuse-never-substitute held live.** `Ghostly Absent Family` → handler error, and
  `fontStyle` reads **`Bold`** afterwards. ⭐ That is the distinguishing fact: had this
  tool grown `setCharacters`'s fallback path, `Inter/Regular` is exactly what would be
  sitting there instead.

⭐ **The two refusals arrived at DIFFERENT LAYERS, as designed.** The bad enum was
rejected by Zod *before dispatch* (`layer: "schema"`, MCP `-32602`); the unloadable font
was refused by the plugin and caught into an error result (`layer: "handler"`). That is
the trap that scored correct behaviour as FAIL three times in this project — the gate
records the distinction instead of flattening it.

- ✅ **`fontSubstituted: false` present live**, asserted as *present*, not merely falsy.
- ✅ **Half a font pair and a zero-property call both refused**, at the handler.
- ✅ **The published schema** — read from `listTools`, never the source — carries no range
  offsets (D2), `{value, unit}` objects (3.4), and a description stating the refusal
  policy.

### ⛔ The first run FAILED, and on the gate rather than the tool

`create_text` answers **prose** (`Created text "x" with ID: …`) while `create_page` embeds
JSON; the gate assumed one shape for both. Recorded because the abort proved something
worth keeping: **CC5 held on a failed run** — the scratch page was still deleted in the
`finally` and the baseline still restored.

🔴 **That run also exposed a far worse latent defect in the gate.** The read-back reached
for plugin-API names (`fontName`, `textCase`, `paragraphIndent`) against a node exported
as `JSON_REST_V1`, whose `filterFigmaNode` keeps only a REST `style` subset. Every field
would have read `null` — and **null-before compared with null-after passes vacuously**, a
symmetric failure that reads exactly like agreement. The fix is not just correct field
names: `assertReadChannelWorks` now proves the channel reports real values *before* any
equality is trusted, and the six fields REST cannot carry are witnessed separately
through the plugin's own `before` snapshot taken after each refusal.

⚠️ **One read-back caveat, stated rather than smoothed over:** `letterSpacing: {value: -2,
unit: "PERCENT"}` reads back through REST as `-0.64` — resolved **pixels**, not percent.
The plugin's own snapshot preserves `{unit: "PERCENT", value: -2}`, so the unit survives
the write; it is the REST channel that resolves it. The gate therefore compares the
resolved value on that channel, not the unit it sent.

### ✅ Phase 2's CC6 debt — half closed, and the half that is not

- ✅ **10 293 faces / 2 273 families** against a fixture of **8**. 🔴 The inventory is
  **above `get_available_fonts`'s own 5000 `limit` ceiling**, so the whole inventory
  cannot be returned in one call on this host: paging is **mandatory**, and the
  deterministic code-unit sort is load-bearing rather than theoretical.
- ✅ **`offset` paging is repeatable** (two identical requests, identical faces) and
  **advances**, and the window never rewrites the whole-inventory totals.
- ✅ **Case sensitivity is real and silent:** `inter` (lowercase) reads as an **absent
  family**, indistinguishable from a font that does not exist.
- 🔴 **NOT closed: `available` ≠ `loadable` did not reproduce.** Every listed face loaded;
  every unlisted one refused. The split is *justified* — `Inter/Blond` vs
  `Ghostly Absent Family` prove the two fields answer different questions — but "listed
  yet unloadable" remains **fixture-only**. ⛔ Do not record this debt as discharged.

### ⛔ Standing debts the gate did NOT close

- 🔴 **Mixed-font unification STAYS fixture-only.** The fork ships **no range-font
  setter**, so a mixed node cannot be authored by these tools. The gate looks for one in
  the document and, if it finds one, **clones it onto the scratch page** and unifies the
  clone — the original is never written to. It is now an explicit `--mixed-node=<id>`
  opt-in rather than a search: the first run's automatic `scan_text_nodes` over a real
  page **timed out**, and a two-minute hunt for an opportunistic extra is the wrong
  trade. None was named on this run, so `wasMixed: true` and the `"MIXED"` sentinel are
  proven offline and **unproven live**.
- 🔴 **F3's reachability is unchanged.** The offline harness *injects* the refused
  character write; nothing here can make real Figma refuse one on demand, so whether that
  branch is reachable in production remains unestablished.
