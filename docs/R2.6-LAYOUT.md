**Accepted 2026-08-22.** Four tools for the geometry a frame imposes on its children:
`set_layout_child`, `set_constraints`, `set_size_limits`, `set_clips_content`. All four are
promoted `additive-preview` → `stable`, which is the acceptance act (CC1).

- **Contract:** `1.8.0`, unchanged by acceptance. The bump was spent in item 2.0 on
  `create_text`'s twelve typography parameters; every tool since has been additive.
- **Tools:** 60 (56 at the start of Phase 2). **Plugin commands:** 59.
- **Accepted pair:** `r2-server-975ccb3ce8b9` ↔ `r2-plugin-1eee5a6f3bd9`,
  fingerprint `sha256:f229f6ec…2453ebd`.
- **Offline:** 287/287, `bun run verify` passed, `dist/` rebuilt.
- **Live:** **6/6 gates passed on the accepted build**, channel `sa6ggz00`.

## The four tools

| Item | Tool | What it answers | Gate (first pass) |
|---|---|---|---|
| 2.1 | `set_layout_child` | how a child behaves inside auto-layout | `mzg3tlfl` |
| 2.2 | `set_constraints` | how a node resizes with its parent frame | `2bcdtr5b` |
| 2.3 | `set_size_limits` | a node's min/max width and height | `o2vws4ph` |
| 2.4 | `set_clips_content` | whether a frame clips what overflows it | `u2k66m3w` |

Item 2.0 (`create_text` on the typography surface) belongs to this release too and was
gated on `7l9ymck4`; it is recorded in `R2.5-TYPOGRAPHY.md`'s lineage rather than here
because it widened an existing tool instead of adding one.

### Decisions that differ deliberately between neighbours

These four tools answer adjacent questions and the answers are **not** uniform. Each
divergence was taken with the owner before building, and the reason matters more than the
choice:

- **In-flow auto-layout child.** 2.1 accepts it; 2.2 **refuses the whole call** — the exact
  inverse — because auto-layout and constraints are mutually exclusive answers to one
  question, while 2.1's parameters *are* the auto-layout answer.
- **Context refusal.** 2.2 and 2.3's neighbours refuse by context; 2.3 deliberately shipped
  **no** context refusal, because "min/max are auto-layout only" was unmeasured and an
  unverified refusal looks authoritative. Its gate then measured the rule and the refusal
  was added — superseded by its own measurement, not by an opinion.
- **`appliedFields`.** Present on 2.3, deliberately **absent** on 2.2 and 2.4. Where every
  field is written on every call, the list is a constant that could never fail; publishing
  it would be decoration that reads as a check.
- **Enum location.** 2.2 puts its enum in Zod (all five values are legal); 2.1 does not.

### The eligibility rule for min/max, as measured

Purely **contextual**, node type irrelevant — writable on auto-layout nodes and their
children. A RECTANGLE *inside* auto-layout is accepted; a TEXT *outside* it is refused.
The handler owns the rule in the validation phase; the harness gates the setter on context,
so forgetting the rule now fails offline.

## What the release cost, and what it taught

Three items in a row shipped a defect that only a live gate could find, and in three of the
four the defect was **in the gate, not the tool**. The recurring shape is one sentence:

> ⛔ **A check whose two outcomes read identically cannot fail in either direction.**

- 2.1's headline check asserted a height *held* after writing `layoutGrow: 0` — but that
  write changes no height, so a clean refusal and a partial write printed the same number.
  The platform claim underneath it was false too.
- 2.4's `independentWidthHeld` compared two values that were both 200, and read "held"
  straight through a real 250 → 200 re-clip.
- 2.4's boolean cannot falsify itself: write `false`, read back `false`, and a tool that
  applied the change is indistinguishable from one that echoed its argument.

The answer each time was to measure in a **different currency** — move the parent and read
who follows; read render geometry through `export_node_as_image`'s preflight; compare
against bounds read immediately before the no-op.

### The CC1 defect, found by its own new guard

`getResultStability` falls through to `stable` for anything unlisted, so `set_layout_child`,
`set_constraints` and `set_size_limits` all shipped **frozen from birth** on reply shapes no
live gate had judged. ⛔ Nothing in `bun run verify` could have caught it: **a silently-wrong
default and a deliberately-right decision produce byte-identical contracts.** The repair was
free only because none of the three appears in any frozen baseline. `tests/contract.test.mjs`
now mechanises the rule and is observed failing against a contract mutated into the shape it
catches.

## Acceptance

### The promotion

The four are removed from `ADDITIVE_PREVIEW_RESULTS` in `scripts/contract-lib.mjs` — deleted
rather than commented out, because `getResultStability` falls through to `stable` and a
leftover entry silently holds a tool back at the weaker level.

⛔ **`stable` means frozen.** From here a change to any of these four reply shapes needs a new
`publicContractVersion`, and the walk-back is breaking — `compatibilityErrors()` rejects it
by name. `1.9.0` is reserved for R2.7.

### The pin shape, and why it is the dangerous one

Promotion rewrites `contractPayload.tools`, which `serverBuildId` hashes. It touches no
`capabilityId`, no schema version and no `code.js`. So:

| Pin | Moved? |
|---|---|
| `serverBuildId` | ✅ `fb30663ee0f1` → **`975ccb3ce8b9`** |
| `pluginBuildId` | ⛔ held |
| `serverSchemaVersion` | ⛔ held at `1.8.0` |
| `capabilityFingerprint` | ⛔ held at `sha256:f229f6ec…` |
| tool count | ⛔ held at 60 |

⭐ **This is the shape CC4 exists for, and it was demonstrated rather than argued.** After
regenerating the contract, `dist/server.js` was still the old bundle — and all five gates
refused at `assertRuntime` naming the build ID, before touching the document. A
fingerprint-only check would have run every one of them against a stale server and reported
green on a build nobody promoted.

⭐ Operator consequence, the **opposite** of every layout item: the DEV plugin did **not**
need re-running. Only the server half moved, and the gates spawn their own from `dist/`.

### 🔴 CC7 was MEASURED here, having only ever been asserted

The batch gate's clamp check failed **twice, reproducibly**, at 1990 / 1991 ms against a
1750 ms tolerance — then passed at 1008 ms once Figma was brought to the foreground.
Everything structural was identical across all four runs: same progress frames (0/33/67/100),
same 5 succeeded / 10 skipped, `budgetExhausted: true` throughout. **Only the plugin's own
elapsed time moved, and it moved by exactly 2×.**

| Figma tab | `pluginElapsedMs` |
|---|---|
| backgrounded | 1990, 1991 |
| foregrounded | 1005, 1008 |

⭐ **The tolerance was never touched.** Relaxing 1750 → 2000 would have turned the run green
and permanently destroyed the check's ability to detect a real clamp failure — and the
throttling would have stayed invisible. A reproducible failure is not automatically a defect
in the thing under test; here it was a defect in the *conditions*, and the discriminator was
free. See `feedback_loosening_a_gate_needs_a_known_bad_rerun`.

## Still owed

- 🔴 **The CC3 baseline gap is now SEVEN tools wide, and widening it was a recorded choice.**
  The rule is that each release freezes the previous contract as a baseline. R2.5 was never
  frozen; R2.6 is now accepted without R2.5 or R2.6 being frozen either. So R2.5's three
  tools and R2.6's four are `stable` with **no baseline vouching for them**, parked in
  `ACCEPTED_SINCE_LAST_BASELINE`. ⛔ **R2.7 must freeze both R2.5 and R2.6** to empty that
  list. Freezing changes the replay set every future release is checked against, which is its
  own decision with its own verification.
- 🔴 **The read layer cannot witness `clipsContent`.** `filterFigmaNode` keeps a
  `JSON_REST_V1` subset carrying neither `clipsContent` nor `absoluteRenderBounds`, so through
  `get_node_info` both read `undefined` before and after — and undefined-vs-undefined passes
  vacuously. The gate measures through `export_node_as_image`'s preflight instead. Fixing the
  read layer is a result-shape change to a `stable` tool → needs R2.7's `1.9.0`.
- ⏳ **A node inside an INSTANCE is unmeasured** for `set_clips_content`. The matrix nests a
  frame in a plain FRAME because this gate creates no component to instantiate, and an
  instance child is the context most likely to make a readable property unwritable.
- ⏳ **Whether Figma rejects a transient min > max is unmeasurable through this surface.**
  The fork has no other writer for those properties and the tool refuses every path that
  produces the transient, so both readings are identical. The write order is adopted as the
  safe direction, not as a measured fact.
- ⏳ **SCALE vs STRETCH** on a single-axis resize is the one constraint value whose live
  behaviour no geometry check here distinguishes.
- ⚠️ Three older gates remain declared stale and were out of scope: `live-export-gate`
  (R2.1), `live-create-page-gate` (R2.2), `live-plugin-data-gate` (R2.4).

⛔ **Accepting R2.6 does not accept R2.** R2 acceptance is the end of R2.7, and its criterion
names an artifact that does not exist yet: a representative component/page fixture a generic
client can build and edit using only fork tools.
