### 1.1 `set_fill` — ✅✅ BUILT AND GATED 2026-08-23

**Four decisions taken with the owner before building:**

1. **The freeze lands first**, as a separate commit with a separate verification, so
   `set_fill` is developed against an 8-baseline replay set from birth.
2. **`paints: Paint[]`, not a single paint.** Mirrors Figma's own `node.fills = [...]`; a
   real design stacks a gradient over a solid, and adding arity to a `stable` tool later is
   breaking. 1–16 paints, or `null`.
3. **Gradients are aimed by raw `gradientTransform` OR by `angle`, never both** — the
   `create_text` `fontWeight` × `fontFamily` precedent, because a discarded value reads as an
   applied one. The receipt reports which input produced the matrix.
4. **A bound paint style is ALLOWED and MEASURED, not refused** — R2.6 2.2's decision ③
   shape. The receipt carries `styleIdBefore` / `styleIdAfter` / `styleDetached` as three
   readings, and the gate turns them into a claim. ⚠️ 2.3's identical call was superseded by
   its own measurement; that remains the likely outcome here and is the process working.

**What it ships.** `set_fill(nodeId, paints)` — `SOLID` plus all four gradients, one nested
colour shape everywhere. This ends the divergence R2.4's live gate caught: `apply_batch`'s
`set_fill_color` takes `{color:{r,g,b,a}}` while the standalone `set_fill_color` takes flat
`r,g,b,a`, and the contract had been calling them the same shape. ⛔ `set_fill_color` is
`stable` and cannot be repaired, so the divergence is **pinned by a test** and the old tool
is documented as legacy.

**Semantics reused rather than reinvented:** `null` clears, an **empty array is refused**
(R2.3's plugin-data rule — two ways to say one thing lets one be discarded silently), and an
absent `paints` is refused as "wrote nothing".

⭐ **Partial application is structurally impossible** — `node.fills = [...]` is one
assignment, the free guarantee 2.2 and 2.4 had and 2.3 had to work for. The half that is not
free is tested: a bad paint in the **last** slot refuses the whole call with the
side-effect channel empty, because asserting *that* it threw does not assert *when*.

⛔ **The eligibility refusal is deliberately narrow.** Only the genuine surface question —
a node with no `fills` property. Whether any *context* refuses despite the surface being
present is left to the gate. 2.3 is why: it probed whether a node *exposed* `minWidth`, but
Figma exposes all four on every node and gates only the write, so the probe measured nothing
and 4/4 refusals came from the platform mid-write.

**Offline results.** 318/318 tests green (was 287), 31 of them new. **12/12 source mutants
killed with the comment-only CONTROL surviving.** `dist/` byte-identical across three builds.
`bun run verify` passed: 61 tools, 6 prompts, source/runtime parity verified.

🔴 **Two mutants survived the first run, and only one was a real gap.**

- **The "no fills-surface refusal" mutant was an INSTRUMENT ERROR, not a test hole.** Its
  anchor `if (!("fills" in node)) {` appears **verbatim and earlier** in the legacy
  `setFillColor`, so `.replace()` mutated the legacy tool while the label said `set_fill` —
  and the run printed "SURVIVED", i.e. a defect in the wrong function reported as a hole in
  the right one. Anchored on `set_fill`'s own refusal message it dies immediately. ⭐ A
  mutation run is an instrument, and an instrument aimed at the wrong function reports a
  defect in the one it missed.
- **The gradient sign-flip mutant was a REAL gap.** Flipping the sign of `d` in

  test — including the 0° and 90° ones — because those read the ramp position, which is

  unused; for RADIAL, ANGULAR and DIAMOND it is not. ✅ Closed by asserting a **property**
  of what "rotate by θ" means — the linear part's determinant is `1/s²` for a rotation and
  negative for a reflection — rather than comparing against a hardcoded matrix, which would
  only restate the implementation and would have been satisfied by the mutant too.

fixture.** `"fills" in node` was TRUE for a GROUP and a SLICE, so `set_fill`'s only node

execute it — 2.1's debt, which 2.2 paid. Same shape as the blanket `layoutMode: "NONE"` that
hid a real `set_layout_sizing` defect for six releases. `FILL_CARRIERS` now type-gates it.
⚠️ PAGE and SECTION are **absent = unmeasured**, never "does not have it" — the discipline

⭐ **The read-back is held honest by the harness's discarding node, NOT by a platform
claim.** An earlier draft of this handler argued that Figma normalizes paints on assignment

## 2.1 `set_image_fill` — the CROP defect, MEASURED before it was fixed

⛔ **THE CHECKLIST'S FRAMING WAS WRONG, IN A WAY THAT CHANGED THE FIX.** It read: *"the schema
promises a mode the handler cannot deliver."* Figma **accepts** `CROP` and stores it fine. What
was missing is `imageTransform` — the parameter naming *which* region to crop to. With none
supplied the only possible default is the identity matrix, and identity maps the whole image
onto the whole node box, so the render is a **stretch**. The mode was never undeliverable; it
**silently degraded to STRETCH and was reported as CROP**.

Measured live on a scratch page, `set_image_fill` + `get_node_info`:

| Requested | Stored (`JSON_REST_V1`) | `imageTransform` | Rendered |
| --- | --- | --- | --- |
| `CROP` | **`STRETCH`** | `[[1,0,0],[0,1,0]]` identity | whole image squashed — both edge markers visible |
| `FILL` | `FILL` | absent | centre-crop — neither marker visible |

⭐ **A READ-BACK WOULD NOT HAVE CAUGHT THIS.** The plugin node answers `"CROP"`; only the REST
export says `"STRETCH"`. Two id spaces for one stored state — the **third** time this fork has
been bitten by that shape, after 1.2's `effectStyleId` vs `styles.effect`. ⛔ The field that
discriminates a crop from a stretch is the **transform**, never the mode name, which is why the
receipt reports the transform and why a bare `CROP` is now refused rather than defaulted.

🔴 **THE FIRST PROBE WAS WORTHLESS AND SAID SO.** Both exports returned byte-identical
`sha256:992ef0b5…`. The cause was the probe image, not the platform: its colour boundary sat at
the image's horizontal centre, where a squash and a centre-crop produce **the same pixels**. The
experiment had one possible reading. Rebuilt with a black bar at the far left and a white bar at
the far right — a stretch keeps both, a centre-crop keeps neither — and the two states separated
immediately. ⭐ *Ask what reading the BUG would produce; if it equals the fix's, measure in a
different currency.*
