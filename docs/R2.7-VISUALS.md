## Phase 1 — paint and effects

### 1.1 `set_fill` — ✅✅ BUILT AND GATED 2026-08-23

**Four decisions taken with the owner before building:**

1. **The freeze lands first**, as a separate commit with a separate verification, so
   `set_fill` is developed against an 8-baseline replay set from birth.
2. **`paints: Paint[]`, not a single paint.** Mirrors Figma's own `node.fills = [...]`; a
   real design stacks a gradient over a solid, and adding arity to a `stable` tool later is
   breaking. 1–16 paints, or `null`.
3. **Gradients are aimed by raw `gradientTransform` OR by `angle`, never both** — the
   `create_text` `fontWeight` × `fontFamily` precedent, because a discarded value reads as an
   applied one. The receipt reports which input produced the matrix.
4. **A bound paint style is ALLOWED and MEASURED, not refused** — R2.6 2.2's decision ③
   shape. The receipt carries `styleIdBefore` / `styleIdAfter` / `styleDetached` as three
   readings, and the gate turns them into a claim. ⚠️ 2.3's identical call was superseded by
   its own measurement; that remains the likely outcome here and is the process working.

**What it ships.** `set_fill(nodeId, paints)` — `SOLID` plus all four gradients, one nested
colour shape everywhere. This ends the divergence R2.4's live gate caught: `apply_batch`'s
`set_fill_color` takes `{color:{r,g,b,a}}` while the standalone `set_fill_color` takes flat
`r,g,b,a`, and the contract had been calling them the same shape. ⛔ `set_fill_color` is
`stable` and cannot be repaired, so the divergence is **pinned by a test** and the old tool
is documented as legacy.

**Semantics reused rather than reinvented:** `null` clears, an **empty array is refused**
(R2.3's plugin-data rule — two ways to say one thing lets one be discarded silently), and an
absent `paints` is refused as "wrote nothing".

⭐ **Partial application is structurally impossible** — `node.fills = [...]` is one
assignment, the free guarantee 2.2 and 2.4 had and 2.3 had to work for. The half that is not
free is tested: a bad paint in the **last** slot refuses the whole call with the
side-effect channel empty, because asserting *that* it threw does not assert *when*.

⛔ **The eligibility refusal is deliberately narrow.** Only the genuine surface question —
a node with no `fills` property. Whether any *context* refuses despite the surface being
present is left to the gate. 2.3 is why: it probed whether a node *exposed* `minWidth`, but
Figma exposes all four on every node and gates only the write, so the probe measured nothing
and 4/4 refusals came from the platform mid-write.

**Offline results.** 318/318 tests green (was 287), 31 of them new. **12/12 source mutants
killed with the comment-only CONTROL surviving.** `dist/` byte-identical across three builds.
`bun run verify` passed: 61 tools, 6 prompts, source/runtime parity verified.

🔴 **Two mutants survived the first run, and only one was a real gap.**

- **The "no fills-surface refusal" mutant was an INSTRUMENT ERROR, not a test hole.** Its
  anchor `if (!("fills" in node)) {` appears **verbatim and earlier** in the legacy
  `setFillColor`, so `.replace()` mutated the legacy tool while the label said `set_fill` —
  and the run printed "SURVIVED", i.e. a defect in the wrong function reported as a hole in
  the right one. Anchored on `set_fill`'s own refusal message it dies immediately. ⭐ A
  mutation run is an instrument, and an instrument aimed at the wrong function reports a
  defect in the one it missed.
- **The gradient sign-flip mutant was a REAL gap.** Flipping the sign of `d` in
  `gradientTransformFromAngle` turns the rotation into a reflection, and it passed every
  test — including the 0° and 90° ones — because those read the ramp position, which is
  **row 0 only**, and the sign lives in row 1. For a LINEAR gradient row 1 is genuinely
  unused; for RADIAL, ANGULAR and DIAMOND it is not. ✅ Closed by asserting a **property**
  of what "rotate by θ" means — the linear part's determinant is `1/s²` for a rotation and
  negative for a reflection — rather than comparing against a hardcoded matrix, which would
  only restate the implementation and would have been satisfied by the mutant too.

🔴 **The harness was giving every node a blanket `fills: []`, and that was a dishonest
fixture.** `"fills" in node` was TRUE for a GROUP and a SLICE, so `set_fill`'s only node
refusal was unreachable offline and the live gate would have been the first thing ever to
execute it — 2.1's debt, which 2.2 paid. Same shape as the blanket `layoutMode: "NONE"` that
hid a real `set_layout_sizing` defect for six releases. `FILL_CARRIERS` now type-gates it.
⚠️ PAGE and SECTION are **absent = unmeasured**, never "does not have it" — the discipline
`CLIPS_CONTENT_CARRIERS` adopted for SECTION.

⭐ **The read-back is held honest by the harness's discarding node, NOT by a platform
claim.** An earlier draft of this handler argued that Figma normalizes paints on assignment
so an echo and a read-back would differ by eye. That is a platform claim, and resting the
tool's honesty on one is what 2.3 shipped. `ignoreFillWrites` — 2.4's instrument — needs
none: a node that accepts the write and keeps its old fills reports the old array through a
read-back and the new one through an echo, in one reading.

**⛔ NO CONTRACT BUMP — the schema HELD at `1.8.0`.** A new tool is additive. R2.7 is the
release that spends `1.8.0` → `1.9.0`, but item 1.1 has nothing to bump *for*; the bump
belongs to whichever item changes a `stable` tool's result shape, and the `filterFigmaNode`
read-layer repair is already named for it.

#### ✅ §6 — THE ANGLE CONVENTION IS MEASURED, AND IT MATCHES THE SCHEMA

The published claim was arithmetic until this run. It is now a reading:

| angle | rendered | schema claim |
| --- | --- | --- |
| `0` | red **LEFT** → blue right | left-to-right ✅ |
| `90` | red **TOP** → blue bottom | top-to-bottom ✅ |
| `270` | blue top → red bottom | exact mirror of 90 ✅ |

⭐ **This positively excludes the sign-flipped convention** — the mutant that survived the
entire offline suite. A flipped sign would have put blue at the top at 90°. ⛔ The gate
still carries no PNG decoder: it proves *distinguishability* mechanically and asserts
0/90/270 render to three different byte strings, and the DIRECTION comes from looking at the
three PNGs it retains. Re-confirm by eye if `gradientTransformFromAngle` is ever touched —
the offline determinant check proves the transform is *a* rotation, never which way it turns.

#### ✅ §2 — the read layer CAN witness this tool's property, unlike `clipsContent`

`readChannel.usable: true` — `get_node_info` carries `fills` through `filterFigmaNode`'s
`JSON_REST_V1` subset and reported a real change across the write. ⭐ Worth stating because
the expectation from R2.6 2.4 was the opposite: there the subset carried **neither**
`clipsContent` nor `absoluteRenderBounds`, so before and after both read `undefined` and the
comparison passed vacuously. The instrument check ran first regardless, and would have said
so. ⚠️ The `filterFigmaNode` repair still owed to R2.7's `1.9.0` is therefore **narrower
than recorded** — it is about `clipsContent` / `absoluteRenderBounds`, not about fills.

#### 🔴 §4 — three handler refusal messages are UNREACHABLE through the transport

`emptyArray`, `badBlendMode` and `outOfRange` all refuse at the **schema** layer: Zod's
`.min(1)`, the blend-mode enum and the `.min(0).max(1)` channel bounds fire before the
plugin is reached. So `set_fill`'s handler messages for those three — *"Pass null to remove
every fill…"*, *"Figma colour channels are 0-1 floats, not 0-255 bytes"* — are **never what
an MCP caller sees**.

⚠️ **Not a defect, and the schema is not loosened to expose them.** An earlier structured
refusal is the better outcome, and the handler checks remain correct defence-in-depth because
the plugin dispatcher is a second entry point. ⛔ **What it does mean** is that the offline
tests asserting those messages exercise that second entry point only and say nothing about
the caller's experience — the same correction `create_text`'s gate made when it noted a
schema-layer refusal *"proves nothing about the handler"*.

⭐ **The check that reports this is an OWNERSHIP MISMATCH, not a description.** Each refusal
declares which layer should own it, and the gate fails on any disagreement — so a handler
refusal that silently became unreachable, or a schema bound that stopped validating, both
break it. An instrument that merely printed the observed layers would print the same thing
whether the split were right or catastrophically wrong.
✅ **Observed FAILING** before it was trusted: declaring `alphaCollision` as `schema` made
the gate report `alphaCollision (declared schema, observed handler)` and exit non-zero.

Also measured: the write **resolves in pixels** (red and blue render to different bytes)
against an **untouched CONTROL** that held byte-identical throughout; a refused call leaves
the render byte-identical; and `paints: null` both reports `cleared` and changes the render.

#### ⏳ §5 `styleDetached` — still UNMEASURED, and the gate may not be able to close it

`paintStyleCount: 0` — the file has no local paint styles, so there was nothing to bind and

⛔ **The blocker is structural, not incidental: no fork tool BINDS a paint style.** That is

⭐ **The tool is correct under either answer regardless**, which is the whole reason the

readings instead of asserting a rule. ⛔ But the question is open, and **promoting `set_fill`
to `stable` at R2 acceptance does not close it.**
